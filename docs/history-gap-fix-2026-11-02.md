# Исправление уведомлений о недоступной истории

## Подтверждённая причина

Скрины владельца показали повторяющиеся `Fetch error: Request was rejected` поверх графиков.
В логе тестовой сборки 8100224 запрос начинался с 2026-10-27 23:59:59.474 UTC. Архив следующего дня, 28 октября, был недоступен. HEAD-проверка при разборе 01.11: архив 28.10 — HTTP 404, 29.10 — HTTP 200 (без скачивания ZIP).
После ошибки архива fallback обращался в aggTrades с тем же старым from. Binance отвечал HTTP 400, code -4166: разрешены только последние 2 дня. Обычный retry возвращал запрос через ~2.5 с, сообщения перекрывали график.
Это отдельная причина от ранее найденных ложных NoMatch маршрутизации.

## Изменения

- Fallback в REST проверяет доступный диапазон для фьючерсов. Если история слишком старая, возвращается типизированный HistoryUnavailable; запрос заведомо недоступного REST-диапазона не отправляется. Spot не ограничен новым фьючерсным правилом.
- 404 архива запоминается на 5 минут, затем проверяется снова; раньше запись оставалась до завершения процесса.
- Тип ошибки сохраняется для обычных сделок, RefTrades и BubbleSummary до обработки панелью.
- Зарегистрированные запросы получают паузу 5 минут. Данные/coverage не помечаются пустыми или полностью загруженными.
- Повторные проверки RequestHandler во время cooldown пишутся на TRACE вместо ERROR: сама причина уже сообщена.
- Вместо красных одинаковых ошибок — жёлтое предупреждение с символом, датой UTC и временем повтора. Дубликаты активного уведомления не добавляются.
- Неблокирующая отметка History incomplete с подробностями при наведении хранится отдельно от статуса текущей загрузки. Другой индикатор не очищает её. Смена инструмента/контента очищает её; успешное завершение того же диапазона Trades/RefTrades снимает соответствующую отметку. Для BubbleSummary без полного подтверждения coverage отметка остаётся консервативно до смены/повторного открытия панели.
- Устаревшее предупреждение зарегистрированного запроса не применяется к изменившемуся графику.

## Проверки и границы

517 passed, 15 ignored, 0 failed (`history-gap-verified.log`). Проверены выбор fallback для spot/linear/inverse, истечение отрицательного кэша, длинный cooldown без ложного completed/empty, типизированная ошибка, сохранение уведомления при других загрузках и дедупликация.
Реальная отсутствующая история не восстановлена этим патчем; требуется доступный источник. Архивы не подменялись и сделки не выдумывались.
Новый UI пока не проверен в живом окне: тестовый процесс старой сборки открыт, принудительно не закрывался.

## Установка только в тестовый профиль

`node scripts/rebuild-test-when-closed.mjs <PID>` ждёт штатного завершения указанного тестового процесса, сохраняет его state и прежний exe в `.local/snapshots`, затем вызывает обычную сборку/запуск тестового профиля.
Второй ожидающий обновитель блокируется файлом `.local/test-rebuild-waiter.lock`. Рабочий app-dev не меняется.
Следующий запуск использует INFO: DEBUG-лог smoke за несколько часов вырос примерно до 900 МБ; активный лог не удалялся и не обрезался.
