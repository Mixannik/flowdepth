# Рабочий и тестовый профили

Профиль — отдельный каталог настроек, рыночного кэша, архивов, индикаторов пользователя и логов.
Без параметров сохраняется прежний каталог `%APPDATA%\flowsurface` на Windows.

## Выбор

```powershell
.\target\release\flowsurface.exe --profile-dir "C:\path\to\test-profile"
```

Приоритет: `--profile-dir` → существующая `FLOWSURFACE_DATA_PATH` → стандартный каталог.
Путь фиксируется при старте и преобразуется в абсолютный. Пустой путь, пропущенный аргумент или неизвестный параметр останавливают запуск, а не переключают его на рабочий профиль.
Для явного профиля логи всегда лежат в `<profile>\logs`, даже при унаследованной `FLOWSURFACE_LOG_DIR`.
Для обычного запуска прежняя настройка отдельного каталога логов сохраняется.
В заголовке окна явного профиля добавляется имя его каталога.

## Один процесс на профиль

До открытия логов, state, кэша и запуска очистки приложение берёт эксклюзивную блокировку файла `profile.lock`.
Второй процесс с тем же профилем сообщает причину и завершается с кодом 2, не трогая файлы сессии первого.
На Windows сообщение выводится отдельным системным диалогом, поскольку release-приложение не имеет консоли.
Разные профили можно запускать параллельно. Внутренний Restart не создаёт второй процесс и сохраняет блокировку.
Блокировку освобождает ОС при закрытии или завершении процесса. Сам файл остаётся: его наличие не означает, что профиль занят. Удалять его для обхода блокировки нельзя.

Важно: старая сборка без этой защиты не соблюдает lock. При первом переходе на новую рабочую сборку старую нужно штатно закрыть.
Профили изолируют файлы приложения, но не системное хранилище учётных данных: ключи proxy/server/QuantWheel пока используют общие записи keychain. Не менять их в тестовом профиле до отдельной изоляции.

## Подготовленная песочница проекта

Путь: `<repository>\.local\test-profile`; каталог исключён из Git.
Скрипт копирует только saved-state из стандартного профиля и только если в тестовом профиле его ещё нет. Кэш и логи рабочего терминала не копируются и не очищаются.

Подготовить без открытия окна:

```powershell
node scripts/test-profile.mjs --prepare-only
```

Собрать текущие исходники и открыть тестовый терминал:

```powershell
node scripts/test-profile.mjs
```

Сборка пишется в `test-profile-build.log`. Рабочий exe в app-dev не заменяется.
Скрипт передаёт как CLI-параметр, так и переменные данных/логов; это дополнительно защищает путь при случайном использовании старого бинарника.
Повторный запуск не перезаписывает тестовую раскладку свежим снимком рабочего профиля.

## Проверки

Тесты создают только временные каталоги и запускают дочерние тестовые процессы без GUI/сети:

- повторное открытие профиля блокируется, контрольные state/cache/log не изменяются;
- разные профили могут быть заняты одновременно;
- после обычного освобождения и выхода дочернего процесса без Rust-деструкторов профиль доступен снова;
- CLI имеет приоритет над переменной окружения, state/cache/log используют выбранный каталог;
- внешний override логов не выводит запись за пределы явного профиля.

Визуальная проверка заголовка и системного сообщения ещё требуется в тестовом приложении; захват экрана пользователя не выполняется.
