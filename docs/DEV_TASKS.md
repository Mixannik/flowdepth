## Правила

Выбранную пользователем FD-задачу выполнять автономно по AGENTS.md: анализ, решение, внутренние контракты/Event/API и архитектура, тесты, проверка, статусы и документация. К следующему этапу той же задачи переходить без согласований. Остановка — только риск необратимой потери пользовательских данных, несовместимость внешнего публичного API, недостаток критической информации или выход за задачу. Commit/push/merge/release, удаление пользовательских данных и изменение рабочего профиля требуют отдельного разрешения. После завершения — отчёт до 10 строк и остановка; следующая FD-задача только по указанию владельца.

`Backlog → Ready → In Progress → Verification → Done`; отдельно `Blocked` с причиной, условием разблокировки и предыдущим состоянием. Неудачная Verification возвращает задачу в In Progress. Ready: определены вход, границы, зависимости и критерии. In Progress: назначен исполнитель и записан исходный commit. Verification: указан проверяемый commit/diff и фактические результаты. Done: результат проверен, необходимые тесты выполнены, ограничения записаны; непройденная обязательная проверка означает Verification/Blocked, а не Done.

Для кода: форматирование затронутого, целевые регрессии с фиксированными входами; команды выбирать по REVIEW и риску, учитывать feature unification. Для документации: ссылки/пути и diff, cargo не нужен. UI — отдельный профиль и приёмка без захвата экрана пользователя. Рабочие exe/state/кэш не менять. Полный workspace и строгий Clippy не запускать автоматически.

## Связь с GitHub без двух статусов

Пока Issues не созданы, состояние живёт только в этой таблице. После разрешения публикации: одна Issue на FD-ID; её тело содержит состояние процесса, зависимости, критерии и журнал проверок. Здесь строка заменяется ссылкой `FD-ID → #N`, полем «статус: в Issue» и кратким названием; состояния и результаты сюда больше не копируются. Реестр A-ID хранит свидетельства, не статус исполнения. Closed Issue допустима только после Done; Blocked остаётся открытой. GitHub Projects для этого не требуется.

Заготовка тела существующего Issue-шаблона: `FD-ID / A-ID; исходный commit; рынок/символ/UTC/единицы; наблюдение; ожидаемый результат; границы; зависимости; состояние; критерии; команды и результаты; ограничения; PR`. Ветка `codex/fd-NNN-краткая-тема`, PR с FD-ID, ссылкой Issue и фактическими проверками. Публикация и merge требуют отдельного разрешения владельца.
