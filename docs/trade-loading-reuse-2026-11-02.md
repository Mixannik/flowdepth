## Изменение

Перед очередным REST-запросом Binance worker перепроверяет не больше минуты ближайшего диапазона в общем кэше. Только для последних двух дней и raw со стабильными ID. Непрерывно покрытый префикс отдаётся потребителю через прежний фильтр биржевых ID и исходных пропусков. Курсор продвигается, счётчик отсутствия прогресса сбрасывается.

Последняя миллисекунда префикса остаётся для следующего запроса: там могут быть другие исполнения, не попавшие на предыдущую REST-страницу. Если кэш содержит только собственную конечную миллисекунду, дырку у левой границы, агрегаты или записи без ID, повторное использование не включается. Проверки QuantityContext окружают чтение.

85-секундный лимит сети и retryable tail сохраняются. Прогресс из кэша можно выдать до проверки этого лимита. Старые архивы и server/Arrow сохраняют прежний путь. Это уменьшает повторные загрузки пересекающихся недавних хвостов; не объединяет ещё не выполнявшиеся запросы и не ускоряет первый холодный запрос при отсутствии данных в кэше. Дополнительное чтение кэша имеет стоимость, фактический эффект требует сравнения после установки.

В журнал добавлен `TRADE CacheReuse` с диапазоном, req и числом переданных записей. По нему и Worker Done/requests сравнивать повторные загрузки после обновления.
