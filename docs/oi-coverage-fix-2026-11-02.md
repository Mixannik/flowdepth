Пользователь: OI обрывается на всех вкладках. Точная визуальная граница не названа. В журнале test-profile сборки 916dd9b найдены Cache Hit с одной точкой OI на запрошенные большие диапазоны: сохранённое coverage не соответствовало данным.

## Проверка источника

Прямой запрос BinanceLinear BTCUSDT, 15m, 23.10.2026 09:54:30 — 02.11.2026 09:54:30 UTC вернул 500 точек только с 28.10 05:00 до 02.11 09:45. API возвращает последние 500 точек, даже если указать более широкий диапазон.

Контроль исправленного окна 23.10 10:00 — 28.10 14:45 UTC (ровно 500 временных отметок) вернул 500 точек с обеими границами. Источник за этот период доступен.

Официальный контракт: максимум 500 записей, история примерно за последний месяц. Более старые данные возможны из прежнего локального кэша, но не восстанавливаются этим API: [Binance OI Statistics](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Open-Interest-Statistics).

## Изменения

- Binance OI запрашивается временными окнами максимум по 500 отметок; границы включительные, следующая страница начинается со следующей отметки. Учитывается исходный TF OI (минимум 5m), не TF отображения 1m/3m. Другие адаптеры сохраняют свои пути загрузки.
- Исправлен подсчёт limit: два соседних включительных timestamp требуют двух записей, а не одной.
- OI coverage сохраняется только для непрерывных полученных участков. Пропуски в начале/внутри не становятся «загружено». Пустой ответ не создаёт отрицательное покрытие.
- Ключ OI стал `open_interest_v2`. Реальные выровненные точки старого кэша по запросу переносятся в пропуски новой версии, покрытие строится заново по самим точкам. Старые файлы и записи не удаляются; сохранившийся OI старше месяца остаётся доступен.
- Чтение включает опорную точку исходного TF перед невыравненной левой границей. Данные не интерполируются и не заменяются нулями.
