# Аудит индикаторов и смысла данных — 01.11.2026

Статический разбор локального кода. Рабочий терминал, настройки и рыночные данные не изменялись. Тесты в этом проходе не запускались; перечислено существующее покрытие. Наличие формулы/теста не подтверждает торговую полезность.

## Как устроено

- Footprint хранит объёмы по цене и сторону агрессора; `src/chart/kline.rs` координирует рисование, уровни и исследования. `src/chart/kline/*` — преимущественно функции расчёта/отрисовки; `src/chart/indicator/kline/*` — индикаторы со своим состоянием, запросами и callback на ответ.
- `SpotCvd` получает дельту своего рынка из buy/sell свечи, иначе footprint; другой рынок — отдельные свечи. Суммы стартуют с первого общего времени. Линии нормируются независимо по видимой области; сравнивать можно форму, а не высоту как абсолютный объём (`spot_cvd.rs:96`, `:123`, `:411`). Дельта-столбики тоже имеют отдельные масштабы.
- `SizeCvd` сам запрашивает сделки обоих рынков: сначала хвост, затем историю до 3 дней, опрос 10 секунд. Расчёт складывает мелкие корзины в четыре группы (`size_cvd.rs:77`, `:320`). «Один ордер» — эвристика одной стороны в одну миллисекунду, а не биржевой order id (`data/src/chart/kline.rs:342`). Пороги основаны на BTCUSDT 30 октября, но применяются и к другим символам (`:267`).
- Weekly/Monthly VWAP = средневзвешенная типичная цена часовой свечи `(H+L+C)/3`, полосы — дисперсия этих типичных цен. Это приближение, отличающееся от VWAP по всем сделкам (`htf_vwap.rs:52`, `:129`). Session VWAP имеет отдельный путь по сделкам.
- FRVP длиннее 3 дней распределяет часовой объём равномерно по диапазону цены, максимум 300 строк (`range_levels.rs:19`, `src/chart/kline.rs:5257`). Naked levels также распределяет свечной объём равномерно, если нет footprint, и сводит сессию примерно к 200 строкам (`naked_levels.rs:92`). POC/VA здесь приближённые.
- Signals: absorption — концентрация агрессивного объёма на краю с закрытием на противоположном краю; trapped — выход за 5 прошлых баров и возврат за следующие до 3 баров; exhaustion — тонкий экстремум за 10 баров. Это ценовые/объёмные эвристики, не прямое наблюдение удерживаемого лимитного ордера (`signals.rs:165`).
- Стек — 3 диагональных дисбаланса подряд с порогом объёма; unfinished auction — двусторонняя торговля на точном экстремуме (`zones.rs:107`, `:173`). Шаг анализа фиксирован относительно зума, но пересчитывается по последним 300 барам (`:270`).
- OI bars сопоставляет направление цены/дельты с изменением OI между его отсчётами. Названия New longs/Short covering/Long liquidation — классификация сочетания признаков, не доказательство конкретных открытий или принудительных ликвидаций (`oi_bars.rs:45`, `:93`). Failed auctions использует только закрытые бары и период жизни уровня (`failed_auction.rs:51`, `:114`).

## Приоритетные замечания

1. **Высокий приоритет: неполный период выглядит полным.** `period_levels.rs:103` пропускает только полностью пустой период: один день из месяца уже даёт PMH/PML. `naked_levels.rs:179` принимает любые присутствующие бары завершённой сессии без проверки её начала/дыр. Нужны признаки покрытия и запрет авторитетного уровня при неполных данных либо явная пометка. Подтверждённый риск реализации, не утверждение, что текущие данные неполны.
2. **Высокий приоритет: исторические Signals около текущих уровней.** `src/chart/kline.rs:2404` собирает один список актуальных цен, `signals.rs:371` применяет его ко всем видимым историческим барам. Старые сигналы могут появляться/пропадать при изменении сегодняшнего VWAP/period/naked/FRVP. Для истории нужны уровни, действовавшие на момент бара; иначе чёткая трактовка «история рядом с текущими уровнями».
3. **Средний: Trapped может менять прошлую отметку.** `signals.rs:194` использует будущие бары и рисует отметку на исходном. Подтверждение может появиться после первого следующего бара и исчезнуть, если второй/третий обновит экстремум. Нужны отдельные время события/подтверждения и политика предварительного сигнала. Исторический просмотр нельзя трактовать как доступный тогда сигнал.
4. **Средний: пропуски другого рынка сглажены линией.** `spot_cvd.rs:135` подставляет нулевую дельту при отсутствии свечи; при отрисовке `:444` отсутствующий пункт пропускается без разрыва пути. Линия соединяет края дыр, создавая видимость непрерывности. Лучше разрывать путь и показывать покрытие.
5. **Средний: SizeCvd не ограничивает фактическое хранение тремя днями.** `size_cvd.rs:90` только добавляет в `bars`, `:116` каждый раз перестраивает всю series; `window_from` в `:337` задаёт загрузку, но старые бары не удаляются. При долгом запуске память/стоимость перестроения растут. Нужна ограниченная история с определённой базой CVD.
6. **Средний: идентичность участников не доказана размером.** Retail/Whales означает размер агрегата по эвристике, а не владельца заявки. Для других тикеров нынешние BTC-пороги могут быть неуместны. Полезны нейтральные подписи диапазонов и настройки по инструменту.
7. **Ниже: история может измениться при изменении шага анализа.** `zones.rs:270` использует последние 300 диапазонов для всех баров. Смена режима волатильности может изменить старые стеки/exhaustion при том же зуме. Для воспроизводимого исследования нужен зафиксированный или исторически определённый шаг.

## Что уже проверяется тестами и чего не хватает

Есть unit tests для правил absorption/trapped/exhaustion, стеков, незавершённых аукционов, failed auctions, календарных границ period levels, naked levels, сброса VWAP, общего начала CVD, плана загрузки SizeCvd. Примеры: `signals.rs:671`, `zones.rs:490`, `failed_auction.rs:274`, `period_levels.rs:313`, `htf_vwap.rs:233`, `size_cvd.rs:505`.

Следующий полезный слой: воспроизведение одного набора сделок по путям live → backfill → compact → cache с сопоставлением результата; неполные сессии; дыры reference-свечей; момент подтверждения trapped; исторические уровни; длительный SizeCvd. Сравнения с MMT/Coinglass делать на одном символе, UTC-баре, единицах и одинаковом источнике/шаге: название функции само по себе не гарантирует совпадение формул.
