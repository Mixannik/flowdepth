Удаление оригинала при неудаче карантина убрано. Формат кэша и расчёты не менялись.
Добавлены проверки: второе открытие сохраняет файл/контрольную запись, неподдерживаемая схема сохраняется, ошибка пути не приводит к карантину, классификация ошибок не зависит от текста.
Рабочая сборка не заменена; реальный кэш и настройки не затрагивались.

### A2b: восстановление без перезаписи оригинала

Реализован явный путь сохранения восстановленной сессии: загрузчик → layout → приложение. При предупреждениях исходный saved-state не переписывается ни при загрузке, ни при выходе; текущая сессия сохраняется отдельно в `saved-state.session-*.json`.
Неизвестные поля, которые serde раньше игнорировал, определяются по отсутствию в сериализуемой модели и тоже включают защиту. Исходные неизвестные настройки остаются в оригинале и защищённой копии, а не в адаптированной модели сессии.
Копия оригинала обязательна для recovery/migration; если её создать не удалось, существующий экран ошибки загрузки запрещает обычное автоматическое сохранение до явного выбора пользователя.
Предмиграционные, восстановленные и сессионные файлы исключены из обычной ротации; сессионные сохранения используют свой rolling backup и не затирают backup оригинала.
Ограничение: отдельная восстановленная сессия не становится основной автоматически. Следующий запуск снова читает оригинал; выбора/управления восстановленными сессиями в UI пока нет. Предупреждение сообщает путь сохранения.
Живой интерфейс уведомления не проверялся: отдельный тестовый профиль ещё не реализован, рабочее окно не запускали. Рабочий exe и реальные настройки не заменялись.
Проверено: `cargo test --release --workspace --locked` — 495 passed, 12 ignored, 0 failed (`state-a2b-verified.log`). Форматирование и `git diff --check` выполнены. Далее A3: изолированный профиль и блокировка второго экземпляра на профиль.
