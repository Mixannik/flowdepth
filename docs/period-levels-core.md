# C1: расчёт уровней прошлых периодов

02.11.2026. Первый расчётный модуль, выделенный из UI: `data/src/analysis/period_levels.rs`. Использует только std/chrono, получает время явно; не обращается к окну, сети, кэшу или системным часам.

## Вход и результат

Вход — дневные свечи (UTC open time, high, low) и `now`. Результат для прошлого дня, недели с понедельника и календарного месяца содержит полуоткрытый исходный диапазон, ожидаемые/валидные дни, конкретные отсутствующие/некорректные дни и подтверждённые уровни.

Для high/low нужны все дни периода, конечные положительные цены и high ≥ low. Частичная неделя/месяц не даёт подтверждённых уровней. Полные периоды независимы: дыра в прошлом месяце не убирает корректные уровни вчера и прошлой недели.

Текущая незакрытая дневная свеча и будущие/невыравненные timestamp не принимаются в модель. После смены UTC-дня бывшая формирующаяся свеча должна загрузиться заново уже закрытой; старый внутридневной снимок не становится автоматически полным вчерашним днём.

`PeriodLevels` владеет исходными дневками и текущим снимком. Текущий результат пересчитывается только при изменении данных или UTC-дня. Исторический расчёт выполняется явным запросом `at(time)`, используя только данные до этого времени. UI-адаптер переводит Kline во вход модели, запрашивает недостающую историю и читает готовые текущие уровни для рисования/фильтров.

## Интеграция

- `PeriodLevelsIndicator` больше не вычисляет текущие экстремумы при отрисовке/получении reference_prices.
- Дозагрузка проверяет полноту всех включённых периодов вместо наличия последней дневки. Повтор — раз в минуту через существующий RequestHandler.
- Рисование, reference_prices (Only near levels) и исторические auction_levels используют одну политику: только полные периоды.
- Общие UTC-календарные функции перенесены в расчётный модуль; HTF VWAP использует их, его формула и политика полноты пока не менялись.
- Необязательный `data_warning` у индикаторов передаёт сведения о покрытии через KlineChart в существующую жёлтую отметку `History incomplete` в шапке. Tooltip называет период, UTC-даты и число валидных дневок; неполные уровни не участвуют в сигналах. Предупреждение исчезает после восстановления данных или отключения соответствующего периода, независимо от остальных загрузок. Неподдерживаемый режим графика не выдаёт это предупреждение как обычную неполноту.

Рабочий цикл: трейдер сравнивает PD/PW/PM с ценой; основной экран остаётся графиком. Цена ошибки — принять частичный экстремум за уровень полного периода. Нет данных и частичная история обозначаются неблокирующим предупреждением, нормальные уровни остальных периодов остаются видны. Автоматическая попытка загрузки не требует ручного сброса настроек.

## Проверки и ограничения

Контрольные полные уровни совпадают с прежними значениями. Проверяются пропущенный день и ремонт, невалидные цены, UTC-недели/граница года/високосный февраль, незакрытая свеча при смене суток, влияние config на загрузку/предупреждение, исключение неполных уровней из reference и failed-auction источников, неизменность снимка при чтении. Полный workspace: 531 passed, 15 ignored, 0 failed (`period-core-verified.log`); fmt/diff проверены.

Строгая полнота означает, что у недавно появившегося инструмента первый неполный календарный месяц не рисуется как полноценный PMH/PML. Восстановление данных биржи и общая агрегация её запросов остаются в существующем слое загрузки. Исторические auction-запросы пока считают снимки по требованию, отдельного общего кэша исторических расчётов нет.

Раскладка и формулы полных периодов не меняются, миграция state/cache не нужна. Живую отрисовку и tooltip нужно проверить на новой test-profile сборке после штатного закрытия старой; экран пользователя автоматически не захватывается.
