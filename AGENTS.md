# Codex — Flowdepth

Личный Rust/iced-форк для анализа ордерфлоу (MMT/JDK, Coinglass). Отвечай по-русски, кратко.

## Экономная работа
- Начинай с `git status --short`. Сохраняй чужие изменения; без reset/clean и коммитов без запроса.
- Не сканируй весь проект заново. По задаче выбери слой ниже, ищи через `rg -n` в нём; читай нужные разделы/диапазоны, а не большие файлы целиком.
- Карта и пути данных: `docs/project-guide.md`; актуальные результаты/ограничения: нужный раздел `docs/state.md`. Старые аудиты и планы могут отставать от реализации.
- Общий обзор: `README.md`; при ревью: `REVIEW.md`; локальные справочные заметки: нужный раздел `CLAUDE.md`. Не загружай все документы по умолчанию.
- Меняй только относящееся к задаче. Масштабный рефакторинг — с разрешения. Не создавай лишние файлы, отчёты, зависимости и копии документации.
- Сначала уточни из контекста рынок, символ, период, UTC-время, единицы и ожидаемый результат; спроси только недостающее. Проверяй источник/настройки → лог/кэш → код, по одной дешёвой проверке на гипотезу.

## Навигация
- `exchange/`: REST/WS/архивы, биржевые типы, цена/количество, контекст источника.
- `data/`: модели, агрегация, конфигурация, профиль/state; `data/src/analysis/` — выделенные расчёты.
- `indicator-engine/`: компилятор/runtime языка `.ind`; руководство — его `README.md` и `LANGUAGE.md`.
- `src/connector/`: история, backfill, повторы, redb-кэш; `src/main.rs` — события и маршрутизация.
- `src/layout.rs`, `src/screen/dashboard*`: раскладки, панели, подписки; `src/chart/`, `src/widget/chart/` — графики и взаимодействие; `src/indicators/editors/` — настройки.
- Зависимости: приложение → data/exchange/indicator-engine; data → exchange/indicator-engine. Data также зависит от iced_core: отделение ядра ещё продолжается.
- По теме: архитектура → `docs/core-architecture.md`; единицы/агрегация → `docs/quantity-contract.md`; профили приложения → `docs/profiles.md`; расчёты профиля объёма → `docs/profile-core-batch.md`; уровни/VWAP → `docs/period-levels-core.md`, `docs/htf-vwap-core.md`; функции → `docs/orderflow-roadmap.md`; рабочее пространство → `docs/terminal-workspace.md`.

## Корректность и безопасность
- Сохраняй суммы buy/sell, volume/delta, дедупликацию, UTC-границы, семантику spot/linear/inverse и Base/Quote. Не считай Quote всегда USD.
- Сверяй live/history/cache/compaction; учитывай потери деталей при сжатии. Нет данных ≠ ноль; неполный диапазон ≠ полный; свечное приближение ≠ профиль сделок.
- Не публикуй неполные/приближённые уровни как подтверждённые. Сохраняй время подтверждения сигналов, coverage, поколения источников, отмену и отсев устаревших ответов.
- Не исправляй биржевые дыры выдуманными данными. Сохраняй совместимость saved-state и оригиналы при ошибках хранения.
- Рабочий exe: `C:\Users\MSI\Flowdepth\app-dev\flowsurface.exe`; профиль: `%APPDATA%\flowsurface`; лог: `logs\flowsurface-current.log`. Графики — UTC, обычный рабочий лог — МСК (UTC+3).
- Для запуска используй отдельный профиль по `docs/profiles.md`. Не меняй рабочие exe/state/кэш автоматически; приложение сохраняет state при штатном закрытии. Не завершай его принудительно; не запускай два ожидающих обновителя. Тестовые профили пока разделяют системный keychain.
- Не снимай экран пользователя; при необходимости попроси скрин. Не выводи секреты и не прикладывай полный state.
- При отрисовке учитывай: iced `Frame::with_clip` теряет трансформ графика в chart-space.

## Проверки и отчёт
- Используй закреплённый `rust-toolchain.toml`; при необходимости добавь `$env:USERPROFILE\.cargo\bin` в PATH текущей PowerShell-сессии.
- Для документации достаточно проверить ссылки/пути и diff; сборка и тесты не нужны.
- Для кода выбирай минимальные проверки по риску: форматирование затронутого, целевые тесты; расчёты проверяй фиксированными входами и контрольными суммами. Изолированные пакеты могут зависеть от workspace feature unification.
- Полные команды для обоснованной проверки — в `REVIEW.md`. Не запускай полную сборку, весь workspace или строгий Clippy автоматически; не устанавливай зависимости без необходимости. Известные lint-проблемы не исправляй попутно.
- Перед сдачей проверь diff и статус. Кратко сообщи результат, выполненные проверки и ограничения; не называй старые результаты тестов текущими. Обновляй существующий тематический документ только при изменении его контракта/статуса.
